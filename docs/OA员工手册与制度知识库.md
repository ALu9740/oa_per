# OA员工管理系统 员工手册与使用制度

> 文档版本：v1.0 ｜ 适用对象：全体员工与管理员 ｜ 系统：OA-PER 员工管理系统

## 一、系统概述

本系统为公司内部的轻量化 OA 员工管理系统，系统名称为 OA-PER，当前版本 v0.0.1。

系统功能范围包括：员工管理、部门管理、职位管理、个人中心（资料/密码/头像）、权限控制，以及 AI 智能服务（AI 问答、智能助手、知识库）。

系统技术构成如下：后端采用 Spring Boot 3.5 + MyBatisPlus 框架，前端采用 Vue 3 + Vite + Element Plus，数据库为 MySQL，缓存使用 Redis，文件对象存储使用 MinIO。

本系统属于人员管理类系统，不包含考勤打卡、假期申请、报销审批、薪酬发放等 HR 业务模块。涉及假期、薪酬、报销的问题请咨询人事部门，以正式人事制度文件为准。

## 二、角色与权限制度

本系统设两种角色：管理员和普通员工。

管理员拥有系统全部功能权限，具体包括：

1. 员工管理：查询员工、新增员工、编辑员工信息、删除员工（单条与批量）、启用/禁用员工账号；
2. 部门管理：查询部门、新增部门、编辑部门、删除部门（单条与批量）；
3. 职位管理：查询职位、新增职位、编辑职位、删除职位（单条与批量）；
4. 知识库管理：上传制度文档、删除制度文档；
5. 智能助手（AI Agent）：通过自然语言指令让 AI 查询和修改员工、部门、职位数据。

普通员工仅拥有以下权限：

1. 登录系统；
2. 查看、修改本人个人信息（含联系方式）；
3. 修改本人登录密码；
4. 上传/更换本人头像；
5. 使用 AI 问答功能咨询制度与系统使用问题。

普通员工无法进入员工管理、部门管理、职位管理、知识库管理等系统管理页面：访问管理菜单会被自动跳转到首页，直接调用管理接口会被后端拦截（返回 403 无权限）。管理类页面与菜单仅对管理员可见。

## 三、账号与登录制度

### 3.1 登录方式

员工使用注册邮箱（账号）和密码登录系统。未登录状态下访问任何受保护页面，系统会自动拦截并跳转到登录页，需完成登录后才能进入主页。登录失败时系统会给出具体错误提示（如账号或密码错误）。

### 3.2 初始密码

管理员为员工创建账号（新增员工）时，系统自动生成员工编号并使用统一初始密码：123456。

新员工首次登录成功后，应立即通过「个人信息 → 修改密码」修改初始密码，避免账号安全风险。

### 3.3 密码修改制度

员工修改密码需在「个人信息 → 修改密码」页面进行，需依次输入原密码、新密码、确认新密码。原密码由后端校验，校验不通过则无法修改；新密码与确认密码必须一致。密码修改成功后请使用新密码重新登录。

### 3.4 忘记密码

忘记密码的员工可在登录页点击「忘记密码」，通过注册邮箱接收验证码完成身份验证并重置密码。重置完成后即可用新密码登录。

### 3.5 账号状态制度

员工账号有启用与禁用两种状态，由管理员在员工管理中设置：

1. 账号被禁用后，该员工无法再登录系统，已登录的会话在刷新页面后会被强制退出；
2. 账号被禁用不影响员工档案数据，管理员可随时重新启用；
3. 新注册账号需先完善个人资料方可进入系统主页。

如遇账号无法登录且确认密码输入正确，请联系管理员核实账号是否被禁用。

## 四、个人信息管理规范

### 4.1 可查看的信息

员工可在「个人信息」页面查看本人以下资料：姓名、性别、部门、职位、员工编号、入职时间、手机号、邮箱、账号状态。

### 4.2 资料修改规范

员工可修改本人手机号、邮箱等联系方式资料。修改手机号须符合国内手机号格式：以 1 开头的 11 位数字（第二位为 3-9）。姓名、性别、部门、职位、员工编号、入职时间等档案信息由员工所在部门与系统管理员维护，员工本人无权自行修改；如需变更部门或职位，请联系管理员在员工管理中操作。

### 4.3 员工编号规则

员工编号由系统自动生成（全局唯一的长整型编号字符串），在管理员新增员工时产生，员工不可自定义、不可修改。员工编号是员工在系统内的唯一标识，查询工单或咨询管理员时可提供该编号。

### 4.4 头像上传规范

员工可在「个人信息」页面上传或更换本人头像，规范如下：

1. 仅支持图片格式文件；
2. 单个文件大小不得超过 2MB；
3. 头像文件保存于公司对象存储（MinIO），通过系统后端代理访问，保障文件安全；
4. 上传成功后立即在页面回显，无需刷新。

头像上传失败时请先检查：文件是否为图片格式、文件大小是否超过 2MB、网络是否正常。

## 五、部门管理制度

部门由管理员统一管理，部门信息包含部门名称与部门描述。

1. 部门列表支持分页展示与按名称模糊查询；
2. 新增部门需填写部门名称（必填）与部门描述（选填），创建时间由系统自动记录；
3. 编辑部门可修改部门名称与描述；
4. 部门删除受业务校验约束：当部门下仍存在员工时，该部门禁止删除，系统会提示「该部门下存在员工，无法删除」。

部门删除的正确操作流程：先将该部门下的员工调离到其他部门（或删除离职员工档案），确认部门下已无员工，再执行删除部门操作。

## 六、职位管理制度

职位为基础数据，由管理员统一维护，供员工档案引用。

1. 职位信息包含职位名称与排序值；排序值为 0 到 9999 的非负整数，数值越小排列越靠前，用于控制员工新增/编辑时职位下拉选择的展示顺序；排序值仅在新增/编辑职位时填写，职位列表中不展示；
2. 职位列表支持分页展示与按职位名称模糊查询；
3. 删除职位受业务校验约束：当职位下仍存在员工时，该职位禁止删除，系统会提示「该职位下存在员工，无法删除」。需先将相关员工调整到其他职位后再删除；
4. 管理员新增或编辑员工时，职位通过下拉框选择，下拉数据来源于职位管理中维护的职位列表。

## 七、AI 功能使用制度

### 7.1 AI 问答（全体员工可用）

「AI 问答」基于公司制度知识库检索回答问题，具有以下特性：

1. 只读不写：AI 问答仅检索知识库文档内容进行总结回答，不会修改系统任何数据；
2. 适用范围：公司制度、办事流程、系统操作类问题（如密码怎么改、头像怎么传、部门为什么删不掉）；
3. 回答依据：以管理员上传到知识库的正式文档为准，知识库中未涉及的问题 AI 会如实告知暂无相关制度；
4. 会话管理：支持多会话，历史会话与消息可随时查看，也可删除会话。

### 7.2 智能助手（仅管理员可用）

「智能助手」是具备执行能力的 ReAct 智能体，管理员可用自然语言下达指令，由 AI 自动拆解步骤并执行：

1. 支持查询类指令：如「查询名叫张三的员工信息」「统计各部门的员工人数」；
2. 支持修改类指令：如「把张三调到技术部」「新增职位：数据分析师，排序为 1」，AI 会自动完成查员工、查部门、执行调动等步骤；
3. 执行过程透明：AI 调用工具的每一步（如查询员工、查询部门）会实时展示；
4. 安全提示：修改类指令会真实变更系统数据，操作完成后建议管理员到对应管理页面人工复核结果。

### 7.3 知识库管理（仅管理员可用）

知识库文档由管理员统一维护，是 AI 问答的内容来源：

1. 支持上传 pdf、doc、docx、txt、md 格式的制度文档，单个文件不超过 20MB；
2. 文档上传后系统自动完成文本解析、内容分块、向量化入库，入库成功后状态显示「已入库」；
3. 解析失败会显示「失败」状态，可删除后重新上传；
4. 删除文档后，AI 问答将不再检索该文档内容。

各部门如有新制度需进入知识库，请联系管理员上传正式制度文件。

## 八、常见问题（FAQ）

问：新员工的初始密码是什么？
答：初始密码统一为 123456。首次登录后请立即到「个人信息 → 修改密码」处修改。

问：忘记密码了怎么办？
答：在登录页点击「忘记密码」，通过注册邮箱接收验证码验证身份后重置密码。

问：账号密码正确却登录不了，是什么原因？
答：常见原因是账号被管理员禁用，请联系管理员核实账号状态。

问：怎么修改自己的登录密码？
答：进入「个人信息 → 修改密码」，输入原密码、新密码、确认新密码，后端校验通过后修改生效。

问：怎么更换头像？
答：进入「个人信息」页面上传新头像，要求图片格式且不超过 2MB，上传成功后立即回显。

问：头像上传失败怎么办？
答：请确认文件是图片格式、大小不超过 2MB、网络正常后重试。

问：员工编号可以自己修改吗？
答：不可以。员工编号由系统自动生成、全局唯一，作为员工在系统内的唯一标识，不支持自定义或修改。

问：想换部门或换职位，在哪里操作？
答：员工本人无权修改部门与职位，请联系管理员在「员工管理」中调整。

问：部门为什么删除不了？
答：该部门下还存在员工，系统禁止删除。需先将员工调离或删除员工档案，再删除部门。

问：职位为什么删除不了？
答：该职位下还存在员工，系统禁止删除。需先将相关员工调整到其他职位，再删除该职位。

问：手机号填错了保存不了？
答：手机号须为以 1 开头的 11 位数字（第二位 3-9），请检查格式后重新填写。

问：年假怎么申请、试用期多长、报销流程是什么？
答：本系统为人员管理系统，不含假期、试用期、报销等业务模块。相关问题请咨询人事部门，以正式人事制度文件与劳动合同为准。

问：AI 问答回答的内容可信吗？
答：AI 问答基于管理员上传的正式制度文档检索生成，重要事项请以正式制度文件为准；发现知识库内容缺失或过时，请联系管理员更新文档。

问：普通员工可以使用智能助手修改数据吗？
答：不可以。智能助手仅对管理员开放，普通员工只能使用只读的 AI 问答功能。
